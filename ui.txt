0. MENTAL MODEL
--------------------------------------------------------------------------------
- One static shell (index.html) + one stylesheet (design tokens + components)
  + one SPA script (app.js). No bundler, no npm frontend deps.
- Data flows one way: view functions fetch JSON from /api/* or /auth/* and
  render HTML strings into #app. Section 8 lists every endpoint used.
- Theming is a single attribute: <html data-theme="dark|light">. Persisted in
  localStorage key "bs-theme". Toggle button in the topbar.
- Feedback primitives: toast() for all success/error notices (alert() is
  BANNED — never reintroduce it), confirmDialog() for destructive actions,
  skeleton() for loading states, emptyState() when lists are empty.

3. COMPONENT CATALOG (class → appearance → usage)
--------------------------------------------------------------------------------
3.1 .pill + tones (.tone-info .tone-ok .tone-warn .tone-bad .tone-mut .tone-vio)
  Small 12px bold rounded-full label with tinted translucent background +
  colored border (border-color: currentColor). .blink adds 1.6s pulse (used
  for in-progress pipeline states). Every one of the 19 issue statuses maps
  to a label+tone in the STATUS table in app.js (e.g. AWAITING_APPROVAL →
  "Needs approval" amber blinking; RESOLVED_AND_DEPLOYED → "Live" green).
3.2 .card — section container (surface, border, 12px radius, shadow, 18px
  padding, 14px vertical margin). Headings inside have top margin removed.
3.3 .stat-cards > .stat — overview KPIs: 26px extra-bold number + 13px muted
  label, auto-fit min 150px columns.
3.4 table.tbl — full-width, 14px, muted uppercase 12.5px headers, row dividers
  in --line, row hover → --card2. Monospace (.mono) used for IDs/SHAs/URLs.
3.5 Forms: label.f (13px semibold label + .hint muted 12px helper stacked),
  .grid-form (auto-fit min 230px), inputs/selects/textarea (9px radius, bg2
  background, line border, inherit font). .check for checkboxes (auto-width
  box + text). .toolbar (filter row, end-aligned). .btn primary (accent bg,
  dark bold text, brightness hover), .btn.ghost (transparent + border),
  .btn.danger (bad-red bg, white text), .btn.sm / .icon-btn small variants.
3.6 .callout — bordered box with 4px colored left border + card2 background.
  Variants: default info blue, .warn amber, .bad red, .ok green. Used for
  status reasons, approval prompts, "pipeline running" notices, scanner hits.
3.7 .timeline — 3px --line spine with 18px left padding; each .step has an
  11px dot (::before) colored by class: .s-ok green, .s-bad red, .s-warn
  amber, .s-info blue. Mapping fn stepClass() matches status keywords
  (ok/pass/approve/done/live → ok; fail/reject/invalid/error/timeout → bad;
  pause/wait/concern/unverified/warn/skip/empty → warn; else info).
  Name bold + status + muted summary line.
3.8 .diff — unified-diff viewer: bordered scrollable box (max-height 520px),
  monospace 12.5px table with TWO line-number gutters (.ln, 44px, muted,
  bg2, unselectable). Rows: .add (green tint), .del (red tint), .hunk
  (accent-colored @@ header), context plain. Word-wrap on (no sideways
  scroll trap). Built by parseDiff() which tracks old/new line numbers from
  @@ -a,b +c,d @@ headers; '---'/'+++' skipped, '\ No newline' rendered muted.
3.9 .factor — risk breakdown row: grid "reason … ±points" + full-width .bar
  (6px track in bg2, fill accent; .neg green for negative-point factors).
  Bar width normalized to the largest |points| in the list.
3.10 .dist — status distribution rows: 190px label | flexible .track (9px
  rounded bar, accent fill) | count. .hist — 14-day issue histogram: flex
  bars (accent, 85% opacity), 90px tall, tooltips with counts.
3.11 .kv — definition grid (auto-fit min 200px): dt muted 12.5px, dd wrapping
  anywhere (long URLs/SHAs never overflow).
3.12 .snippet — relative wrapper; .copy-btn absolute top-right over <pre>.
3.13 .skel — shimmer loading bars (gradient sweep 1.2s). .empty — centered
  muted icon (30px) + bold title + helper text.
3.14 #toasts .toast — card2 surface, shadow, colored 4px left border by type
  (.ok/.warn/.bad, default info), slide-in animation, auto-dismiss ~4.2s
  with fade. Stacked top-right.
3.15 .live badge — pill with 8px dot: .on green pulsing ("live"), .retry
  amber ("connecting"/"retrying"), default gray ("offline"). Driven by WS
  state machine in app.js (setLive/connectWs/scheduleRetry with capped
  backoff min(30s, 2s×retries)).

5. BEHAVIOR RULES (must preserve in any rework)
--------------------------------------------------------------------------------
- api() injects X-Requested-With + credentials; on 401 (and not already on
  login) it redirects to #/login and throws "Session expired".
- route() runs per-route cleanup (polling timers) BEFORE rendering; every
  view starts with skeleton() then try/catch → error empty-state card.
- Never re-render while the user types (approval comments, filters, forms):
  both the WS handler and the poll tick check document.activeElement.
- Every destructive action goes through confirmDialog (revoke key, reject,
  revert). Approve needs no confirm (comment optional but prompted).
- badgecounts: nav Issues link shows pending-approval count; refreshed after
  boot, after mutations, and on WS events (best-effort, silent catch).
- Theme toggle flips data-theme + localStorage; default dark.
- Timestamps: relative everywhere (timeAgo), absolute in title tooltips.
- Escape EVERYTHING interpolated into HTML with esc() (reports are untrusted
  input — prompt-injection text must never become markup).
- pre.code stays dark in light mode (diffs/JSON readability).

6. RESPONSIVE (bottom of styles.css)
--------------------------------------------------------------------------------
- ≤760px: layout collapses to one column; sidebar becomes a horizontal
  scrollable nav (static position); main padding 14px; user chip hidden;
  distribution rows narrow (130px labels).
- prefers-reduced-motion: ALL animations off (pulse, slide-in, shimmer).
- Tables scroll within cards on narrow screens (overflow via .diff/.code;
  plain .tbl may overflow — wrap future wide tables in a scroll container).

7. KNOWN GAPS / SUGGESTED NEXT EDITS (do not treat as bugs in this handoff)
--------------------------------------------------------------------------------
- Members table has no delete/disable button (no DELETE member endpoint exists
  server-side; adding one is a BACKEND change — out of UI scope).
- No per-site delete button (no DELETE website endpoint either).
- Role pills on the Team table reuse status pill tones via a label-swap hack
  (search "replace(/>[^<]*</" in app.js) — works but fragile; a tiny
  rolePill() helper would be cleaner.
- pre.code in light mode keeps dark background ON PURPOSE (see §1).
- .vio token is currently unused — intended for future AI-accented elements.
- Long issue titles/table cells can overflow on very narrow screens; the
  .tbl wrapper suggestion above covers it.
- Render deploy checks show "Optional" (muted) when RENDER_API_KEY is absent
  — deliberate: version.json verification works without it.

GET/POST /api/settings/policy · GET /api/settings/integrations-status ·
GET /api/audit · GET /api/stats/overview → {byStatus[{status,c}],lastDeploy,
health} · GET/POST /api/members · GET /benchmark/results.json (static file) ·
WS /ws (browser cookies auth; events PIPELINE_STEP/ISSUE_UPDATED/
APPROVAL_NEEDED/DEPLOY_STATUS).
STATUS label/tone table in app.js must cover every server status string or
it falls back to a gray pill with the raw value (safe default — extend the
table when adding states, never remove entries).
